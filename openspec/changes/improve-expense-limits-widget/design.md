# Design

## Context

Мотивация и границы описаны в proposal.md. `ExpenseLimits` получает лимиты по periodDate,
показывает все валюты сразу и открывает `ManageExpenseLimitsButton`. Последний хранит независимые
черновики строк и подтверждённые создания по периоду; категория и валюта сохранённого лимита
неизменяемы. `ExpenseLimitRow` сейчас выводит отдельную валюту в каждой строке.

В `entities/expense-limits` уже есть findAll с необязательной currency, findOne, create,
update и delete. Виджет использует total / rest из API; дополнительных расходов для деталей
не требуется. Существующие мутации только инвалидируют budget-кэш, не сохраняя ответ сразу.
Селектор категорий уже исключает архивные категории из создания, но существующие лимиты
архивных категорий остаются видимыми. Архивный статус самого лимита отсутствует.

В проекте есть ChartCurrencySelect / useChartCurrency, account queries, ScrollDialog,
Menu и готовая типографика ExpenseView. Кнопка добавления позиций расхода использует ghost
и self-start — это прямой образец для «Добавить лимит».

## Goals / Non-Goals

**Goals:**
- Один валютный контекст для виджета, деталей и общего управления, с независимыми черновиками строк.
- Повторное использование текущих компонентов и контрактов без дополнительной библиотеки.
- Сохранение FSD: композиция и выбор контекста в widget, управление мутациями в feature,
  ключи и изменение кэша в entity query-модуле, импорты через public API.

**Non-Goals:**
- Архивный режим, фильтрация существующих лимитов по статусу категории и новые lifecycle API.
- Отдельные формы одного лимита, новый порядок строк, список расходов или редактирование категории / валюты.
- Глобальное изменение shared компонентов либо редактора категорий.

## Decisions

### 1. Валюты из счетов, фильтрация по выбранной валюте

Widget использует `useAccountsQueryOptions().findAll()` в текущем budget scope и получает
уникальные currency, отсортированные по ISO. Под «существующими счетами» принимаем все возвращённые
счета: оба типа и архивные, без новой фильтрации. Выбор не зависит от валют профиля, отчётов
или уже созданных лимитов: иначе первый лимит в новой валюте нельзя создать.
Использовать существующий хук выбора: выбранная валюта сохраняется между месяцами, пока
присутствует среди валют счетов. При удалении последнего счёта этой валюты применяется fallback
на первую валюту либо отсутствие выбора. Ошибка refetch с доступным кэшем не считается пустым ответом.

Сохранять общий месячный запрос и фильтровать его результат по currency локально: это
минимально меняет существующий поток и позволяет корректно обновить все открытые представления.
Серверный currency-фильтр допустим контрактом, но здесь не нужен. Данные разных валют никогда
не складываются, прогресс и остаток вычисляются по отдельному лимиту, API-порядок сохраняется.
Валютный суффикс имени строки убрать, денежные значения форматировать в выбранной валюте.

Если счетов нет — показать сообщение о необходимости счёта, не назначать скрытый RUB и
заблокировать открытие создания. Если счета есть, но лимитов валюты нет — пустое состояние
с доступной шестерёнкой для manageLimits. При ошибке / загрузке сохранить оболочку виджета,
контролы, skeleton / QueryError и возможность повторить запрос соответствующего источника.

### 2. Один диалог-хост с просмотром и общим управлением

Сохранить шестерёнку как вход в общее управление. Widget хранит выбранный id и режим
`details | manage`, а feature предоставляет содержимое общего управления отдельно от trigger.
Использовать один ScrollDialog-хост со сменой содержимого, вместо вложения двух scroll-диалогов.
Это позволяет точно повторить крестик / Escape из расхода и избежать конкурирующих focus traps.

Детали состоят из категории, валюты, периода startDate / endDate, total, `total - rest` и rest.
Menu в заголовке доступно только с manageLimits. «Редактировать» меняет режим на manage,
оставляя исходный id для возврата; редактор получает этот id, прокручивает строку в область
видимости и фокусирует её input суммы. Шестерёнка открывает то же содержимое без выбранной строки.
При сохранении одной строки управление не закрывается и остальные черновики сохраняются.

При входе из деталей Escape возвращает к ним, отбрасывая все несохранённые
черновики. Крестик / backdrop закрывают диалог целиком. При входе из шестерёнки Escape закрывает
управление. Нижняя кнопка со стрелкой отсутствует. Pending блокирует все способы выхода. Обычное закрытие возвращает фокус к исходной
строке или шестерёнке; исчезновение строки — к доступному контролу виджета.
Смена scope, месяца или вынужденная смена валюты закрывает старый host и сбрасывает черновики.
Все мутации используют захваченный scope; завершение старой сессии не заполняет новый кэш.

### 3. Общий редактор одной валюты и итог по полям

Фильтровать исходные limits перед созданием drafts; currency всех drafts задаётся из контекста.
Удалить select / текст валюты из строк, но сохранить её в draft и запросах для точности и уникальности.
Подтверждённые создания и локальные черновики должны разделяться не только по месяцу, но и
по валюте и budget scope, чтобы RUB-строка не попадала в USD после повторного открытия.
Сохранить существующие row validation, различение числового изменения и форматирования,
подтверждение удаления, блокировку второй временной строки и сохранность черновика при ошибке.

Над строками разместить спокойный компактный итог «Общая сумма лимитов» и форматированное
значение. Итог вычисляется из текущих значений полей, включая несохранённые изменения и
временную строку без выбранной категории. Любое конечное число участвует в сумме;
пустые и нечисловые значения дают ноль. Пересчёт происходит при вводе, удалении временной
строки и подтверждённом удалении сохранённой. Для пустого списка — ноль, до инициализации
формы — loading / error без ложного нуля.

Кнопка добавления остаётся в конце списка: `variant="ghost"`, `self-start`, plus и текст,
без w-full / outline и без постоянного фона. Сетка компактная, но с достаточными отступами;
фокус и hover используют существующие токены. Header и итог обозначают валютный контекст один раз;
в строках валюта не повторяется. Подписи сведений — text-caption-1 muted, значения — text-body-2,
без декоративной внешней рамки, как в ExpenseView. Для пустых полей сохраняются плейсхолдеры.

### 4. Кэш и удаления

Логику успешного ответа разместить в expense-limits.query.ts: отменять незавершённые старые
чтения, обновлять релевантные cached list/detail по scope и периоду / валюте записи, затем
инвалидировать зависимые данные. Не вставлять лимит в кэш чужой валюты или месяца и не заменять
локальные несохранённые строки refetch-данными. При DELETE удалять запись из релевантных списков
и detail-кэша; при исчезновении открытого origin закрывать детали корректно.

И для строки управления, и для меню деталей использовать одно существующее подтверждение
удаления без имени категории в описании. Ошибка остаётся в подтверждении, pending блокирует
его закрытие; успешно удалённая запись исчезает из списка и итога формы.

## Risks / Trade-offs

- [Валюты лимитов без существующего счёта не будут доступны] → следовать согласованному источнику
  валют; явно показывать отсутствие счетов, не вводить исключения из валют существующих лимитов.
- [Скрытый дефолт RUB в createEmptyExpenseLimitDraft] → передавать currency из контекста явно и
  покрыть создание первого USD-лимита проверкой реального payload.
- [Итог формы может отличаться от действующих лимитов] → показывать сумму введённых значений
  сразу, сохраняя независимое сохранение строк.
- [Два слоя модальных окон ломают Escape и фокус] → один ScrollDialog со сменой view / manage;
  отдельным слоем остаётся только подтверждение.
- [API допускает нулевой total в frontend-схеме для старых данных] → не допускать NaN / Infinity
  прогресса; действующую положительную валидацию формы сохранить.

## Migration Plan

Frontend-изменение без миграции данных и API. После реализации обновить verification.md,
затем отдельно выполнить sync / archive. При откате возвращается прежний общий редактор;
сохранённые лимиты совместимы с прежним UI и backend.

## Row-action follow-up

Reserve the save column immediately before the amount field. The trailing action stays delete
for pristine persisted rows and temporary rows. An edited persisted row shows restore instead,
using its latest successful baselineTotal. Restore updates only the local amount through the
existing onChange path, which clears its relevant server error and updates the live summary.
