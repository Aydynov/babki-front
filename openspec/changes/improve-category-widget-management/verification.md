## Браузер и HTTP

Использована существующая локальная Postman-симуляция `postman/simulations/space-finance.sim.yaml`
с синтетическими категориями, счетами и расходами. Новая Postman-конфигурация и новые зависимости
не добавлялись. Источник мок-контракта описан в `postman/simulations/README.md`.

```sh
postman simulation run postman/simulations/space-finance.sim.yaml --port 4931 --output ndjson
FRONT_BASE_API_URL=http://127.0.0.1:4931/api/api/v1 \
  FRONT_USE_LOCAL_AUTH_TOKEN=false FRONT_LOCAL_AUTH_TOKEN= \
  npm run dev -- --host 127.0.0.1 --port 5181 --strictPort
```

Проверен реальный маршрут `/main?spaceId=<synthetic-space-id>` в Chrome через Playwright:
1440 × 1000 и 320 × 568. После потери соединения с Docker browser connector проверка
продолжена локальным Chrome. Сетевые вызовы приложения проходили через Axios к HTTP-симуляции;
задержки для pending-сценариев удерживали запрос перед отправкой в симуляцию, не подменяя её ответ.

Проверенные сценарии:

- Активный режим скрывает архивные категории; архивный показывает только архивные, меняет
  заголовок, скрывает `+`, предоставляет возврат. В обоих режимах работают клавиатура и фокус.
- При расходах 60 RUB по активной и 40 RUB по архивной категории проценты остаются 60% / 40%,
  а не пересчитываются по видимому подмножеству. Сортировка равных и нулевых сумм проверена моделью.
- Переключение RUB / USD и сохранение выбранной валюты при переходе между активным и архивным списками;
  нулевая сумма архивной категории в USD не смешивается с её RUB-расходами.
- Создание одной категории, просмотр нулевой суммы, редактирование, очистка описания,
  архивация, восстановление, отмена и подтверждение удаления.
- Сохранение блокирует поля, действия, крестик и Escape на время запроса; после завершения
  возвращает в детали. Закрытие возвращает фокус в строку, lifecycle-операции — к archive / back.
- Ошибки сохранения 409 / 500 сохраняют введённые значения; дубликат связан с именем.
  Ошибка удаления связанной категории 409 остаётся в подтверждении с понятным сообщением.
  Проверены также 500 при удалении, повторная попытка и блокировка подтверждения / Escape при pending.
- Палитра: ring и check выбранного значения после повторного открытия, смена выбора,
  стрелки при фокусе внутри RadioGroup, отсутствие выхода за границы экрана.
- Без `manageCategories` доступны детали и архивная навигация, отсутствуют создание и действия изменения.
- Фоновый refetch не меняет несохранённый черновик. Исчезновение выбранной категории закрывает
  детали с фокусом на стабильном переключателе. Смена пространства сбрасывает открытый черновик.
- Первичная загрузка сохраняет header actions; ошибка категории показывает повторную попытку,
  после восстановления сервиса список загружается.
- Пустые активный и архивный списки, месяц без расходов, сохранение режима при смене месяца.
- Открытие и закрытие деталей не добавляет HTTP-запросов, в частности запросов списка расходов.
- Детали и формы используют ScrollDialog; подтверждение удаления сохраняет AlertDialog.
  На 320 px содержимое и действия доступны без горизонтального переполнения диалога;
  палитра остаётся в пределах экрана. На дополнительном размере 320 × 300 проверена реальная
  прокрутка содержимого с доступными крестиком и действиями формы.

## Проверка изменений

Свежая проверка кода выявила потерю отображения успешного ответа при ошибке фонового GET.
Исправление находится в entity query-модуле: scoped cache обновляется из ответа мутации,
перед обновлением отменяются старые чтения, затем инвалидируются зависимые данные.
Сценарий защищён регрессионным тестом. Поведение и решение отражены в design.md.

Прежние компоненты общего списка и массив черновиков удалены; поиск не обнаруживает старых
вызовов. Годовой виджет и селекторы категорий других форм не редактировались; shared ScrollDialog,
Progress и валютный селектор также не изменялись. Generated route tree не редактировался.

## Уточнения интерфейса после проверки

Дополнительная браузерная проверка: `node /tmp/category-followup-check.cjs` (локальный Chrome
через bundled Playwright, та же Postman HTTP-симуляция). Перед изменениями проверка воспроизвела
отсутствующее меню действий; после исправлений весь сценарий проходит.

- Короткие подписи: «Редактировать», «Удалить», «Сохранить». Действия доступны в меню
  заголовка с теми же компонентами и оформлением, что в деталях счёта.
- Сведения используют сетку без внешней рамки, muted text-caption-1 для подписей и text-body-2
  для значений, как в карточке расхода. В браузере проверены вычисленные размеры шрифта,
  а также итоговый вид на 320 px.
- Архивация требует подтверждение: до подтверждения запрос отсутствует, отмена не меняет
  статус. Ответ 500 остаётся в подтверждении с ошибкой, повторная попытка работает. Во время
  запроса отмена и Escape блокируются. Восстановление остаётся прямым действием меню.
- В описании удаления нет имени категории.
- В режиме редактирования Escape и стрелка «Отмена» отбрасывают черновик и возвращают
  к просмотру. Крестик закрывает окно полностью. Фокус при переходе в редактирование
  устанавливается так же, как в карточке расхода; отмена возвращает его к меню.
- Линтер, архитектурная проверка, сборка, пять точечных тестов и strict OpenSpec validation
  повторно проходят после уточнений. Предупреждение сборки о размере чанков сохраняется.
