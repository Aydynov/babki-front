# Design

## Context

Мотивация и границы пользовательских изменений описаны в proposal.md.
DebtDetailsDialog переключает DebtView, DebtEditForm и DebtRepayForm внутри обычного Dialog;
архивирование и отмена погашений сейчас управляются внутри просмотра. Создание имеет отдельный Dialog.
Полная таблица обёрнута в общий CollectionDialog, который используется и другими виджетами.
ScrollDialog уже предоставляет прокрутку, headerActions и панель actions; формы и меню планов — готовые образцы.
Модель погашения инициализирует accountId пустой строкой и фильтрует активные счета по валюте без учёта типа.
Соседняя модель выполнения плана уже выбирает balance, затем saving.

Изменение затрагивает несколько UI-модулей и управление фокусом, поэтому design создаётся явно.

## Goals / Non-Goals

**Goals:**
- Переиспользовать публичные shared-компоненты и существующие паттерны планов с локальными изменениями долгов.
- Согласовать владение состояниями мутаций, закрытием, подтверждениями и фокусом при смене режимов.
- Сделать выбор счёта детерминированным при загрузке, обновлении и сбросе без перезаписи допустимого выбора.

**Non-Goals:**
- Изменения API, схем серверных ответов, денежных эффектов, прав или ограничений жизненного цикла.
- Миграция остальных виджетов и создание универсального движка диалогов или форм.
- Добавление новых полей создания, изменение обязательности срока, правил точности либо нормализации месяца.
- Изменение существующего поведения успешного погашения: частичное возвращает просмотр, полное закрывает окно.
- Перенос отмены отдельных погашений в общее меню долга.

## Decisions

### 1. Прямое использование ScrollDialog в границах долгов

Заменить оболочки просмотра/редактирования/погашения и создания на Base/Content/Layout.
Формы используют flex min-h-0, контент не создаёт вторую вертикальную область прокрутки.
Окно «Все долги» собирается в widgets/debts с ScrollDialog и прежними фильтрами, списком и пагинацией.
Изменять общий CollectionDialog для всех потребителей либо добавлять флаг только ради долгов не требуется.
Это ограничивает регрессии текущим запросом; ширина полной таблицы сохраняется подходящей для списка.

### 2. Управление действиями и навигацией по образцу планов

Использовать shared-меню в headerActions; перенести существующие правила доступности редактирования,
архивирования и удаления. Подтверждения остаются отдельными вложенными окнами.
Обязательная миграция подтверждений на ScrollDialog в этот объём не входит.
Архивирование координировать на уровне DebtDetailsDialog, передавать общий pending в просмотр.
Для отмены погашений передавать pending родителю либо поднимать мутацию на уровень деталей,
чтобы окно не закрывалось в ходе запроса. Не создавать дополнительное хранилище состояния.

Стрелка и Escape формы сбрасывают черновик и ошибки и возвращают просмотр; крестик и фон закрывают всё окно.
Escape меню/селекта/подтверждения обрабатывается верхним popup без второй реакции родителя.
После редактирования фокус возвращается к кнопке меню, после отмены погашения формы — к кнопке «Погасить».
При закрытии деталей возвращать фокус строке списка, при её исчезновении — доступному элементу виджета.
Сохранить текущий результат успешного погашения и обновление кэшей.

### 3. Локальное обновление сведений и истории

Имя должника и статус образуют адаптивный ряд; у каждого поля подпись Caption1 и значение Body2, без бейджа статуса. Автор с actorLabel располагается последним полем,
рядом со сроком на широком экране и последовательно на узком; недоступный автор имеет нейтральную подпись.
Скрывать историю только после успешного ответа с total=0. Проверка только items.length опасна:
пустая страница не должна прятать пагинацию при total>0. Состояния загрузки и ошибки сохраняются.
Отменённые записи считаются историей и не разрешают удаление или изменение principal.

### 4. Общая типографика контролов и доступные подписи

Использовать Input.Label с htmlFor/id, существующие Input.Base/AccountSelect и токены типографики планов.
Для валюты создания использовать shared Select с size="form", как в создании плана; подписка useStore
на валюту обновляет точность и ограничения суммы сразу после выбора.
Валюта суммы находится в подписи. У полей ввода и выбора есть описательные плейсхолдеры;
у переключателя зачисления и группы выбора режима срока — связанные видимые подписи.
Для date/month передать подсказку там, где поддерживает контрол; видимая подпись остаётся основным ориентиром,
поскольку браузер может игнорировать placeholder у нативного поля даты.
У read-only/disabled полей сохраняется подпись. Существующие значения и правила валидации не меняются.

Оба варианта «Дата/Месяц» сейчас уже имеют text-caption-1. Причина видимого различия ещё не подтверждена:
при реализации сравнить computed font-size/font-family/font-weight/line-height обоих состояний и исправить
локальный конфликт стилей, проверив переключение в браузере. Глобальные шрифты не менять.
Все новые русские строки добавить по существующему шаблону i18next.

### 5. Значения по умолчанию погашения остаются в его модели

Расширить getRepayDebtFormValues входным списком счетов и типом balance/saving.
После существующего фильтра валюты и архивности выбирать первый balance, затем первый saving.
Не импортировать модель feature manage-plan в manage-debt: это нарушает границы срезов;
короткая локальная функция проще новой общей абстракции ради двух вызовов.

После успешной асинхронной загрузки подставлять default только если текущий выбор отсутствует или недопустим.
Допустимый ручной выбор сохранять. При обновлении, делающем счёт недоступным, выбирать новый default
либо очищать поле. При загрузке/ошибке не подставлять неподтверждённые данные и блокировать финансовую отправку.
Отсутствие счёта не блокирует некассовое погашение: accountId в таком запросе отсутствует.
Сброс берёт актуальный остаток долга, сегодняшнюю дату, пустое описание, isIncome=true и новый defaultAccountId.
Кнопки в actions соответствуют PlanExecuteForm: ArrowLeft, Undo2 и основная кнопка с Check и текстом «Погасить».

## Risks / Trade-offs

- Вложенные popup могут закрыть два уровня по Escape → повторить паттерн планов и проверить меню, селект и подтверждения.
- Архивирование/отмена сейчас локальны просмотру → включить их pending в блокировку закрытия и конфликтующих действий.
- Асинхронный default может стереть ручной выбор → сверять допустимость текущего accountId перед заменой.
- Ложное скрытие истории → ориентироваться на подтверждённый total, сохранить ошибки и пагинацию.
- Нативные date/month рисуют подсказки по-разному → проверить оба режима; не заменять нативный календарь ради placeholder.
- Node-тесты импортируют TypeScript с alias и могут не запускаться напрямую → документировать рабочий адресный запуск,
  не считать проглоченную ошибку импорта или bare node --test подтверждением покрытия.

## Migration Plan

Изменение поставляется обычным фронтенд-релизом без миграций данных и новых переменных окружения.
При реализации выполнить lint, lint:architecture, build и ручные проверки пяти окон на desktop/mobile.
Адресно проверить выбор счёта и некассовое погашение; сохранить результаты и безопасные скриншоты в verification.md.
Откат — возврат UI и локальной модели к предыдущей версии; серверные данные не требуют преобразований.
