# Design

## Context

Мотивация описана в `proposal.md`. `ExpensesByMonths` сейчас содержит пять записей в `chartConfig` и пять `Bar`. `getMonthlyMetricCurrencies` в отдельной feature проверяет все пять показателей, а его тест явно считает валюту с одним исходящим переводом доступной. Изменение затрагивает оба модуля.

`getMonthlyCurrencySeries` сохраняет поля отчётного bucket без пересчёта `saving`. Контракт `ReportCurrency` требует поля переводов. Существующий график уже показывает «Данные отсутствуют», если выбранной валюты нет.

Основная спецификация `chart-currency-selection` явно требует пять метрик, а `multicurrency-dashboard-reporting` требует видимости переводов. Дельты заменяют эти требования для месячного графика. Более старое противоречие о селекторах в `Simultaneous currency presentation` не относится к этому изменению: сохраняется поведение `chart-currency-selection` и текущего кода.

## Goals / Non-Goals

**Goals:** Согласовать отрисовку и доступность валют с одним набором из трёх показателей, сохранив существующую архитектуру FSD.

**Non-Goals:** Изменение API, общей отчётной модели, расчёта накоплений, других графиков и операций с переводами.

## Decisions

1. Удалить записи `transfersIn` и `transfersOut` из конфигурации и соответствующие `Bar` в виджете. Легенда и tooltip продолжат использовать существующие компоненты Recharts. Скрытие только столбцов оставляло бы лишнюю конфигурацию; отдельная фильтрация tooltip не нужна.
2. В `getMonthlyMetricCurrencies` проверять только `expenses`, `incomes`, `saving` через `!== 0`; сузить локальный интерфейс до этих полей. Отрицательные накопления остаются значимыми данными. Общий API для произвольных метрик не требуется: у helper один месячный потребитель.
3. Сохранить общие отчётные bucket и Zod-схемы. Удаление полей переводов из общей модели затронуло бы контракт вне границ задачи. Значения `saving` брать из отчёта без пересчёта.
4. Сохранить `useChartCurrency`: после исключения валюты с одними переводами он применяет существующие default/ISO fallback правила, а пустой список приводит к существующему пустому состоянию.

## Risks / Trade-offs

- Валюта, ранее доступная только из-за переводов, исчезнет из селектора → это ожидаемо; проверить fallback и пустое состояние.
- Тест доступности валют сейчас закрепляет старое поведение → обновить его и покрыть входящие/исходящие переводы, три сохраняемых показателя, отрицательные накопления и нулевые данные.
- Общего тестового раннера нет → использовать направленную команду для существующих тестов feature, обязательные lint/build и ручную проверку графика; записать ограничения в verification.md.

## Migration Plan

Изменение поставляется обычной сборкой фронтенда без миграции данных и обновления backend. Откат состоит в возврате конфигурации графика и прежнего критерия доступности валют.
