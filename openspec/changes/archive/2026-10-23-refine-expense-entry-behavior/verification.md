## Completed edge-case checks — 2026-10-23

Проверено в браузере с реальным frontend и локальной Postman HTTP simulation. Воспроизведение описано в
`postman/simulations/expense-entry.md`; fixture — `postman/mocks/space-finance/expense-entry-fixtures.cjs`.

- **1.4 — счёт:** при единственном активном saving-счёте начальный выбор пустой; список содержит только этот
  счёт и позволяет выбрать его вручную. При отсутствии активных счетов показано соответствующее сообщение,
  отправка недоступна. Право создания счетов в fixture выключено, поэтому отдельного предложения создать счёт нет.
- **1.5 — участник:** бывший участник остаётся выбранным при открытии; сохранение другого поля не отправляет
  `participantId` и сохраняет исходный ID. Явный выбор себя отправляет ID текущего пользователя. Проверен
  также действующий другой участник. Обычный участник без права переназначения может изменить доступное поле
  чужого расхода, но поле переназначения не предлагается; PATCH не содержит `participantId`, автор сохраняется.
  Проверены payload и сохранённое состояние mock после отправки формы.
- **2.4 — архивная категория:** существующий расход открывается с архивной категорией. Сохранение без смены
  отправляет её исходный ID `000000000000000000000031`. Меню содержит только активную категорию; её выбор
  отправляет ID `000000000000000000000030`. После повторного открытия архивную выбрать обратно невозможно.
  Проверены оба PATCH и состояние mock после сохранения.
- **2.6 — узкий экран:** проверены viewport **320×640** и **390×844**, четыре исходные позиции и добавление пятой.
  Новое название получает фокус и автоматически прокручивается в область видимости. Внешняя обводка целиком
  помещается внутри области прокрутки, Tab переводит фокус в количество без возврата к названию.
  Горизонтального переполнения окна нет. На 320 px выявлены и исправлены обрезание кнопки закрытия
  (перенос элементов header) и обводки после autofocus-scroll (scroll padding).
  [Скриншот 320×640](screenshots/expense-entry-320.png).
