# Proposal

## Why

Поведение форм расходов изменилось в ходе согласованных улучшений, но мастер-спецификации всё ещё требуют
пустой начальный выбор счёта и название бюджета внутри каждой формы. Нужно зафиксировать фактические сценарии
ввода и работы со справочниками, сохранив исторические данные и границы бюджетов.

## What Changes

- При создании расхода подставляется первый активный расчётный счёт текущего пространства; ручной выбор сохраняется.
- Текущий пользователь представлен единственным вариантом «Вы (по умолчанию)»; при отсутствии других вариантов
  участник отображается в поле только для чтения. Редактирование сохраняет прежнее назначение до явной смены.
- Архивные счета и категории скрыты из вариантов выбора; архивная категория существующего расхода остаётся
  допустимым неизменённым значением. Пункт «Выберите счёт» больше не позволяет выбрать пустое значение.
- Добавление позиции переводит фокус в её название и делает поле видимым; последующая работа не перехватывает фокус.
- Формы больше не дублируют название бюджета: общий переключатель остаётся источником видимого контекста,
  а счета, категории и операции по-прежнему ограничены выбранным пространством.
- Расходы и лимиты используют общий кэш категорий; резервные запросы по ID объединяются для одинаковой категории.
- Чисто визуальные изменения таблицы, меню, полей и списка позиций в change не включаются.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `expense-creation`: начальный счёт, правила выбора счёта и фокус после добавления позиции.
- `expense-editing`: архивная категория как неизменённое значение и доступность фокуса в общей форме.
- `group-financial-operations`: варианты участника, единые правила списка счетов и разрешение категорий без N+1.
- `budget-context`: принадлежность формы определяется выбранным пространством без обязательной подписи внутри окна.

## Impact

Изменения реализации уже находятся в рабочем дереве: общая форма расходов, `AccountSelect`, `CategorySelect`,
query-модуль категорий, API-клиенты расходов и лимитов, а также формы, из которых удалена подпись бюджета.
HTTP-контракты и зависимости не меняются. Кэш остаётся изолирован по пользователю и пространству.

Этот change оформляет уже внесённое поведение. При завершении проверок исправлены обнаруженные проблемы
мобильной формы: доступность кнопки закрытия и место для обводки после автоматической прокрутки.
Проверки запросов выполнялись настоящими Axios-клиентами через локальную Postman simulation на синтетических данных.
Мастер-спецификации будут обновляться отдельным шагом синхронизации.
