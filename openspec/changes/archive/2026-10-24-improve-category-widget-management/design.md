# Design

## Context

Мотивация описана в proposal.md. `ExpensesByCategories` уже получает полный список категорий
и месячные суммы через reports; `getSortedMonthlyExpenseCategoryRows` сохраняет порядок равных
сумм. Сейчас список не фильтруется по `isArchived`. Feature `manage-expense-categories` хранит
массив черновиков имени и цвета и открывает общий Dialog через шестерёнку.

Категория уже содержит `description` и `isArchived`; PATCH принимает оба поля. Существующие
scope-aware мутации вызывают `invalidateBudget`. После успешного ответа мутации entity query-модуль
отменяет незавершённые чтения категорий и сразу обновляет scoped list/detail кэш из ответа
(либо удаляет категорию при DELETE), затем инвалидирует зависимые данные. Это сохраняет
результат сохранения даже при ошибке последующего GET; новые методы API не нужны. Виджет счетов предоставляет подходящий образец archive / back,
скрытия `+` и восстановления фокуса. ScrollDialog уже отвечает за прокрутку и панели действий.
В ColorPicker есть RadioGroup и стили `data-checked`, но видимость выделения требует проверки
в браузере: наличие классов само по себе не доказывает правильный результат.

## Goals / Non-Goals

**Goals:**
- Использовать существующие запросы и мутации в текущем budget scope.
- Разделить композицию деталей на уровне widget и изменение категории на уровне feature,
  сохраняя направление FSD и импорты через публичные index.ts.
- Заменить массив редактируемых строк одной формой без дублирования цветовой палитры и ошибок.

**Non-Goals:**
- Запросы списка расходов, новая аналитика, серверные изменения и новые зависимости.
- Перевод всех диалогов приложения на ScrollDialog: охвачены только окна управления категориями.
- Изменения годового отчёта и правил доступности категорий в сторонних селекторах.

## Decisions

### 1. Режим списка хранится в widget

Использовать локальный `active | archived`, по умолчанию active, и фильтровать полный список
перед существующей сортировкой. Смена месяца сохраняет режим; смена budget scope сбрасывает
выбранную категорию и черновик, чтобы не выполнять мутации в другом пространстве.
Архивный переключатель доступен и без права управления. Заголовки и кнопки соответствуют delta spec.
Отдельные маршруты или серверная фильтрация не нужны для уже загруженного списка.

Палитра валют продолжает зависеть от полного месячного отчёта, а знаменатель прогресса — от
полного currency bucket. Пересчёт процентов только по видимым категориям изменил бы смысл отчёта.
Если категорий режима нет, показывать режимное пустое состояние; иначе при отсутствии расходов
сохранять «Данные отсутствуют» без строк. Это сохраняет существующее поведение месяца без валюты.

### 2. Детали используют данные widget, формы — существующие entity mutations

Widget хранит id выбранной категории и ref активированной строки. Диалог деталей получает
актуальную категорию из query data, сумму, месяц и валюту из выбранного bucket; дополнительных
expense-запросов нет. Пустое описание отображается как отсутствие описания, сумма отсутствующей
категории в доступной валюте — как ноль. Действие открытия охватывает всю строку и доступно
с клавиатуры; не вкладывать кнопки в кнопки.

Feature экспортирует создание и действия для одной категории, используя общую форму имени,
цвета и описания с режимами create / edit. Сохранить текущие нормализацию имени, обязательный
цвет, палитру 25 цветов и сопоставление серверных ошибок. Проверять дубликаты по полному списку,
включая архив, исключая собственный id; описание ограничить 500 символами. Пустое описание
при редактировании отправлять явно пустой строкой, чтобы поддерживать очистку значения.
Чужие изменения и фоновые refetch не сбрасывают введённые поля. Прежний массив черновиков и
неиспользуемые компоненты списка удалить после замены, вместо поддержки двух путей управления.

После создания закрыть форму и вернуть фокус к `+`; категория занимает место по общей сортировке.
После редактирования вернуться в актуальные детали. Ошибка сохраняет форму и её значения.

### 3. Архивация и восстановление используют PATCH isArchived

В заголовке деталей показывать меню edit, archive / restore и delete только с `manageCategories`,
по образцу меню счёта. Архивация требует AlertDialog-подтверждение; восстановление остаётся
прямым действием. CategoryConfirmDialog обслуживает подтверждения архивации и удаления,
без имени категории в описании удаления. Ошибки архивации и удаления показывать внутри
соответствующего подтверждения, ошибки восстановления — в деталях.
Pending блокирует конфликтующие действия и закрытие соответствующего окна.

При успешной архивации / восстановлении закрыть детали, сохранить текущий режим и вернуть
фокус к переключателю: прежняя строка больше ему не соответствует. После удаления также
закрыть детали и сфокусировать этот стабильный контрол. Если refetch обнаружил исчезновение
выбранной категории, закрыть детали с тем же fallback. Не направлять фокус на размонтированную строку.

### 4. Общая оболочка диалогов и явная выбранность цвета

Для деталей, создания и редактирования использовать ScrollDialog.Base / Content / Layout,
без дополнительного вложенного scroll-контейнера. В формах submit и cancel расположить в
actions, блокировать крестик и onOpenChange во время запроса. В редактировании крестик
закрывает весь диалог; Escape и стрелка отмены отбрасывают черновик и возвращают к просмотру.
Для сведений использовать сетку без внешней рамки, text-caption-1 для подписей и text-body-2
для значений, как в ExpenseView. Тексты действий: «Редактировать», «Удалить», «Сохранить». Удаление оставить в существующей
оболочке подтверждения; палитра остаётся Popover, а не отдельным модальным окном.

Сохранить RadioGroup и клавиатурную навигацию ColorPicker. Проверить связь выбранного value
и Radio.Root, стили checked и контраст галочки; привести сравнение HEX к единому регистру,
если это требуется существующими значениями. Обводка выбранного цвета должна сохраняться
при открытии, в отличие от временной обводки фокуса. Подтвердить визуально на светлых и тёмных
цветах; не заменять семантику radio собственными кнопками.

## Risks / Trade-offs

- [Скрытые архивные суммы делают сумму видимых процентов меньше 100%] → сохранить смысл доли
  от всех расходов; явно закрепить это в сценариях, не нормализовать заново.
- [Refetch может размонтировать активную строку] → стабильный archive / back ref для lifecycle
  операций и исчезновения категории; обычное закрытие возвращает фокус в строку.
- [Проверка имени зависит от загруженного списка] → сохранить полный query и серверную
  обработку конфликта, не разрешать submit без доступных данных для проверки.
- [Существующий тест импортирует TypeScript из node:test] → использовать совместимый runtime
  и явную точечную команду; не выдавать bare `node --test` за рабочий общий test runner.

## Migration Plan

Изменение выпускается как обычное обновление frontend без миграции данных. Основные specs
обновляются при последующем sync / archive изменения. Откат frontend возвращает прежний UI;
архивные статусы и описания остаются совместимы с текущими схемами и API.
