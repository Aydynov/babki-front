# Design

## Context

Мотивация описана в proposal.md. ManageAccountsButton уже ограничен accountId,
проверяет manageAccounts и использует готовые мутации переименования, архивации
и удаления. Сейчас он открывает обычный Dialog со сведениями и всеми действиями.
AccountDetailsDialog использует ScrollDialog и содержит пять основных полей.
IncomeActions показывает существующий образец Base UI Menu с IcDots20 и отдельной
формой в ScrollDialog. Нужны явные решения о фокусе и состояниях вложенных окон.

## Goals / Non-Goals

**Goals:** переиспользовать существующие мутации и примитивы, ограничить форму
единственным счетом, сохранить корректный фокус между деталями, меню и окнами.

**Non-Goals:** изменение API, прав, исторических расчетов, редактирование атрибутов
кроме названия, восстановление архивных счетов, новые зависимости.

## Decisions

### Меню вместо общего окна управления

Сохранить публичный интерфейс ManageAccountsButton. Его trigger использует
Button.Icon с IcDots20 и доступной подписью «Действия со счетом»; Base UI Menu
выводит пункты в согласованном порядке. Без manageAccounts trigger отсутствует.
Для архивного счета не выводить архивацию. Переиспользовать оформление меню
IncomeActions; не создавать новый универсальный компонент для этого изменения.
Альтернатива — оставить промежуточное окно управления — добавляет лишний переход
и не соответствует согласованному прямому выбору действия.

### Отдельная форма в ScrollDialog

Использовать ScrollDialog.Base, Content и Layout, форму с единственным видимым
label и input названия и кнопкой submit «Сохранить» в actions. Заголовок —
«Редактирование счета». Статичные поля и кнопки жизненного цикла отсутствуют.
При каждом открытии брать сохраненное имя выбранного счета; черновик после
отмены не переносить в следующее открытие. Проверять trim, непустое имя и лимит
100 символов по существующему контракту. Не отправлять запрос для неизмененного
имени. После успешного сохранения закрывать форму и оставлять детали открытыми.
Ошибку показывать в форме, сохраняя ввод. Альтернатива — редактирование прямо
в деталях — не соответствует запросу на отдельное окно.

### Состояния действий и возврат фокуса

Меню закрывается при выборе. Использовать отдельные состояния редактирования
и подтверждения архивации/удаления, не допуская их одновременного открытия.
При сохранении или выполнении действия блокировать повторные действия и закрытие
соответствующего окна крестиком, Escape и нажатием вне него. Сохранить тексты
подтверждений, ошибки и предложение архивации при restricted deletion активного
счета. По отмене или закрытию верхнего окна возвращать фокус на trigger меню
в остающихся открытыми деталях. После успешной архивации/удаления использовать
существующий onUnavailable и возврат фокуса к переключателю списка.

### Статус и обновления

В AccountDetailsDialog добавить шестой факт «Статус» по archivedAt, используя
существующие переводы «активен» / «в архиве». Это текущий статус, даже при просмотре
прошлого месяца. Оставить остальные пять фактов и расчет исторического баланса.
Переименование продолжает отправлять только name и обновлять данные через
существующий query-модуль. Добавить недостающие подписи в локализацию.

## Risks / Trade-offs

- Вложенные модальные окна и закрывающееся меню могут перехватывать фокус →
  явно связать finalFocus с trigger и проверить клавиатуру и Escape вручную.
- Текущий ответ мутации может подменить историческую сумму → проверить, что
  обновление имени сохраняет период и баланс на конец выбранного месяца.
- Архивный счет имеет иной набор действий → проверить обе версии меню и отказ
  в удалении без предложения повторной архивации.

## Migration Plan

Миграция данных не требуется. Изменения поставляются вместе с интерфейсом;
откат — возврат изменений компонентов и локализации без изменения данных.
