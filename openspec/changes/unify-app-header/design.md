# Design

## Context

Мотивация описана в proposal.md. Сейчас `_authenticated.tsx` возвращает только Outlet. `BudgetMainPage` отдельно показывает `BudgetSelector`, а `MainPage` — `Header` с 2FA/выходом. В состоянии без выбранного пространства действия аккаунта продублированы. Ранние возвраты загрузки и ошибки бюджета скрывают их полностью.

`SpacesLayout` внутри `spaces-page.tsx` имеет свою навигацию и заголовки. `/join` — публичный маршрут с собственной проверкой сессии, который показывает `JoinPage` внутри `AuthShell` и авторизованному пользователю. Это нельзя исправить переносом `/join` под обязательный auth guard: гостевой сценарий должен сохраниться.

`BudgetMainPage` уже реализует приоритет URL, восстановление предпочтения, проверку членства, отмену запросов, защиту финансовых форм и восстановление после потери доступа. Меню не должно создавать конкурирующий источник выбранного бюджета. 2FA и выход имеют собственные диалоги, управление секретами и ограничения локального токена.

Общий Header не содержит доменной логики. Общего примитива меню пока нет; Base UI уже установлен. Изменение затрагивает app, pages, widgets и features, поэтому отдельный дизайн нужен для сохранения FSD и поведения сессии.

## Goals / Non-Goals

**Goals:**
- Одна композиция панели выше содержимого страницы и его веток загрузки/ошибок.
- Один маршрутный источник контекста и существующие query keys, без отдельного глобального стора навигации.
- Независимые меню пространства и аккаунта с корректным переходом в существующие диалоги.
- Сохранение русских подписей, существующей палитры и компактности финансового интерфейса.

**Non-Goals:**
- Новые страницы профиля, редактирование пользователя, поиск, уведомления, тема оформления и боковая навигация.
- Перенос выбора месяца/года в панель, переработка финансовых виджетов или бизнес-сценариев приглашений.
- Изменение API, моделей авторизации, автоматическое вступление по приглашению.

## Decisions

Отдельный блок «Ведите бюджет вместе» с кнопкой приглашения и раскрываемой панелью приглашений на дашборде удалён. Приглашения открываются из меню пространства. Для владельца пустого бюджета остаётся только FirstAccountSetup с предложением добавить первый счёт; после появления счёта этот блок скрывается.

Для владельца подтверждённого текущего пространства меню содержит «Пригласить близких» с иконкой. Пункт ведёт к существующей секции приглашений `/spaces/<spaceId>#space-invitations`, не создавая ссылку автоматически. Участникам и вне контекста пространства этот пункт не предлагается.

Анимация основных меню и подменю — только opacity, 150 мс при открытии и закрытии. Масштабирование и переход transform не используются, чтобы размеры и координаты popup оставались стабильными до размонтирования.

Уточнения после реализации: нижние углы панели скруглены. Основные меню открываются с зазором под нижней границей всей панели, включая перенесённую строку действий. Выбор пространства находится в отдельном пункте с иконкой и стрелкой, который открывает подменю справа; на узком экране подменю остаётся в пределах viewport.

### 1. Компактная строка вместо двух уровней

Пользователь выбрал компактную строку. Рассматривались строка и двухуровневая панель с заголовком: второй вариант требует больше вертикального места на насыщенном дашборде. Сохранение раздельных панелей не решает постоянный доступ к аккаунту.

```text
+-------------------------------------------------------------+
| [Space v]                 [Page action]        [Account v]   |
+-------------------------------------------------------------+
| Page title / description                                    |
| Content                                                     |
+-------------------------------------------------------------+
```

Внешний вид: единая белая поверхность с тонкой границей снизу, без отдельных крупных карточек вокруг групп; существующие muted/foreground/border/card токены, PlusJakartaSans и Lucide. Предлагаемые размеры для реализации: высота строки около 60 px, интерактивные области не меньше 44 px, иконки 16–20 px, единые горизонтальные отступы с содержимым страницы. Панель остаётся в обычном потоке; закрепление при прокрутке не входит в начальный вариант. Эти размеры и отсутствие sticky — проектные значения по умолчанию, а не отдельные пожелания пользователя.

На ширине 320 px пространство получает `min-width: 0` и сокращение названия, аккаунт не сжимается и сохраняет доступную подпись. Непоместившееся действие переносится ниже внутри той же панели. Меню ограничены viewport и имеют вертикальную прокрутку. Полное длинное название доступно в открытом меню. Качество оформления достигается иерархией, выравниванием и отступами, без новых декоративных градиентов или акцентной палитры.

### 2. Композиция в app, доменная навигация в features

Создать `widgets/app-header` с публичным API: он компонует меню пространства, меню аккаунта и необязательные действия. Features `manage-spaces` и `auth` владеют своими действиями; при необходимости добавить тонкую обёртку над меню Base UI в shared/ui. Ни shared, ни features не импортируют страницы или маршруты из app.

В app создать небольшой компонент композиции панели, определяющий по текущему маршруту контекст пространства и действие страницы. Использовать его в layout `_authenticated` перед Outlet и в авторизованной ветке `/join`. Не применять регистрацию действий через эффекты, глобальный Zustand-стор или отдельную конфигурационную систему: текущих нескольких маршрутов достаточно для явного сопоставления в app. Страницы не монтируют второй экземпляр панели.

| Маршрут | Контекст слева | Действие страницы |
| --- | --- | --- |
| `/main?spaceId=...` | Проверенное пространство бюджета | Нет обязательного действия |
| `/main` без выбора | «Пространства» | Нет; создание доступно в меню/пустом состоянии |
| `/spaces` | «Пространства» | «Создать пространство», переход на `/spaces/new` |
| `/spaces/new` | «Пространства» | Нет; submit остаётся в форме |
| `/spaces/$spaceId` | Пространство из params | Нет; «Открыть бюджет» рядом с хлебными крошками после подтверждения доступа |
| `/join` после входа | «Пространства» | Нет; проверка/вступление остаются в содержимом |

На новых приватных страницах используется тот же layout с нейтральным контекстом по умолчанию. Заголовки страниц и необходимые локальные ссылки «Назад» остаются в содержимом; старые глобальные блоки BudgetSelector/Header и повторное основное действие заголовка удаляются. Полезные onboarding-блоки FirstAccountSetup не становятся частью навигации и сохраняются.

### 3. Контекст пространства следует URL

Для `/main` использовать текущие валидаторы и resolver предпочтения; для настроек — params страницы. Чтение имени и членства выполняется через существующие `spacesQueryOptions`, общий кэш дедуплицирует запросы. Панель может читать метаданные, но финансовый BudgetProvider и разрешение финансовых запросов остаются под существующей проверкой доступа бюджета.

Переход из меню выбора всегда ведёт на `/main?spaceId=<id>`, в том числе из настроек, каталога и приглашения. Просмотр настроек сам по себе не меняет сохранённый бюджет. Каталог, создание и приглашение не показывают старое предпочтение как контекст текущей страницы. До подтверждения контекстного пространства показывается нейтральная подпись/индикатор, а недоступные настройки и действие «Открыть бюджет» отсутствуют.

Меню содержит список пространств с отметкой текущего, существующую пагинацию для доступа ко всем страницам, затем настройки текущего контекста и ссылки «Все пространства», «Создать пространство», «Присоединиться по приглашению». Последняя только открывает `/join`; без сохранённого приглашения остаётся существующая инструкция открыть ссылку, а не новая форма ввода токена. Ошибка списка с повтором не скрывает остальные группы панели и ссылки. Пустота определяется по total.

Действующий `useBlocker` дашборда продолжает защищать все навигационные переходы, включая Links из новой панели. Переключение пространства недоступно во время отправки финансовой формы; блокировка меню не должна делать аккаунт недоступным. Сохранение периода, сброс старых форм и восстановление при 403/404 остаются в существующем бюджетном потоке. Дублировать эту логику в панели нельзя.

### 4. Меню аккаунта и жизненный цикл диалогов

Триггер показывает инициалы из подтверждённого пользователя; раскрытие содержит имя, email, «Двухфакторная аутентификация» и отделённый пункт «Выйти». Имя/email — информация, не переход к несуществующей странице профиля. В локальном token mode аккаунт виден, но недоступные 2FA и выход скрыты, как требуют существующие спецификации.

Адаптировать публичный API auth-компонентов для меню, сохранив единственный экземпляр каждой state machine. Диалоги монтируются вне размонтируемого popup: выбор пункта закрывает меню и открывает диалог, а закрытие меню не сбрасывает активную форму, provisioning или recovery codes. После закрытия диалога фокус возвращается к постоянному триггеру аккаунта; при отмене выхода сессия и маршрут сохраняются. Нельзя оставлять finalFocus на исчезнувшем menu item. Действующие запреты закрытия при выдаче recovery codes и очистка секретов после допустимого закрытия сохраняются.

Использовать Base UI для клавиатуры, Escape и фокуса. Оба меню имеют локализованные доступные имена, состояние раскрытия и выбранный пункт пространства; для смешанного списка ссылок и выбора применить семантику menu/menuitemradio, не listbox с вложенными кнопками.

### 5. Авторизованный и гостевой /join

Сохранить текущий loader с `userId` и `invitationVersion` и захват fragment. App-композиция добавляет ту же панель только для подтверждённого пользователя. `JoinPage` в этой ветке использует обычный контентный контейнер под панелью; гостевая ветка сохраняет AuthShell. Условие оболочки не должно размонтировать JoinInvitation из-за открытия меню или диалога. Уход со страницы и открытие аккаунта не принимают и не отменяют приглашение; подтверждённый выход очищает его по текущим правилам.

## Risks / Trade-offs

- [Панель выше BudgetProvider теряет контекст] → передавать route-derived spaceId, читать существующий кэш; не вводить второй выбранный бюджет.
- [Меню размонтирует триггер диалога] → диалоги вне popup, явный возврат фокуса на аккаунт, проверка recovery lifecycle.
- [Сохранённое пространство ошибочно выглядит текущим на общих страницах] → нейтральный режим вне main/settings.
- [Ошибка дочерней страницы убирает аккаунт] → общий layout выше pending/error веток, проверка route-level pending/error после подтверждения сессии. Ошибка проверки самой сессии не считается авторизованным состоянием.
- [Новый переход обходит защиту формы] → обычная маршрутизация через существующий blocker; ручная проверка выбора, настроек, каталога и browser back/forward.
- [Пагинация утяжеляет dropdown] → компактная пагинация и ограниченная высота; поиск не добавляется без отдельной потребности.
- [Нет настроенного UI test runner] → обязательные статические проверки и документированная ручная матрица вместо заявления об автоматическом покрытии.

## Migration Plan

Добавить примитив меню и общий виджет, затем подключить layout и авторизованный join, перенести действия и убрать дубли. Все изменения поставляются вместе, без миграции данных или изменения URL. Откат выполняется возвратом UI-композиции и триггеров к прежнему состоянию. Генерируемый routeTree не редактируется вручную.
