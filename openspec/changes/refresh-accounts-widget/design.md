# Design

## Context

Мотивация и пользовательский объем описаны в `proposal.md`. Сейчас `Accounts` запрашивает
`accountsQueryOptions.findAll({ toDate })` и показывает все счета в сетке без преобразования.
`Incomes` использует раскрытие в `CardAmount`, но этот компонент скрывает переключатель без
элементов, не ставит плюс положительным значениям и содержит подпись «всего:».

`Transfer` содержит `source` и `destination` с `accountId`, `amount` и `currency`, а запрос списка
поддерживает `accountId`, границы периода, `page` и `limit` до 100. Существующие mutation hooks
инвалидируют семейства transfer/account queries после изменения перевода. Основная валюта
доступна через `usersQueryOptions.me()`. Месяц определяется `useSelectedPeriod()`.

Дизайн необходим для согласования независимых запросов раскрытия, их состояния при смене периода
и применения ограничения одной страницы к каждому счету.

## Goals / Non-Goals

**Goals:**
- Сохранить один публичный виджет `Accounts` и существующую композицию дашборда.
- Изолировать состояние и запрос истории в строке счета, сохраняя читаемый баланс.
- Использовать существующие DTO, query keys, Base UI и русскую локализацию.

**Non-Goals:**
- Полная выписка по счету, доходы/расходы в раскрытии, итоги движения или новые операции из строки.
- Пагинация, бесконечная прокрутка, новые backend endpoints или изменение API сортировки.
- Изменение управления архивными счетами, shared `CardAmount` или виджета доходов.
- Изменение старого change, синхронизация или архивирование его specs в рамках этой работы.

## Decisions

### 1. Подготовка списка внутри widgets/accounts

Получить счета на конец выбранного месяца и пользователя, отфильтровать `archivedAt !== null`
только для отображения виджета. Исходный query cache остается полным: управление и названия
вторых счетов используют в том числе архивные записи. Построить lookup имен до фильтрации;
для отсутствующего второго счета использовать нейтральную подпись «Другой счет».

Две непустые секции идут в фиксированном порядке `balance`, `saving`. Сортировка внутри секции:
основная валюта первой, далее ISO-код, затем имя через localeCompare текущей локали, затем id.
Не изменять исходный массив из query cache. Брать `defaultCurrency` из профиля;
пока обязательные данные не получены, показывать структурный skeleton без временного порядка RUB.
При недоступном профиле или счетах без кэша показывать ошибку с повторной попыткой внутри оболочки;
при ошибке обновления сохранять кэшированные данные и компактное сообщение.

Альтернатива — менять entity API так, чтобы он всегда исключал архивные счета — затронула бы
управление и исторические подписи, поэтому фильтрация остается локальной.

### 2. Строка счета с независимым Collapsible

Добавить локальный компонент строки в `widgets/accounts/ui`, с Base UI `Collapsible`, общей
кнопкой и индикатором раскрытия. В заголовке строки расположить название, баланс и переключатель;
в панели — список переводов. Счета изначально закрыты; несколько могут быть открыты одновременно.
Переключатель доступен и при пустой истории, имеет локализованное имя и доступное состояние.
При смене месяца сохранить раскрытие для оставшихся счетов, заменив данные панели новым запросом.
Список раскрытых id хранить в `Accounts` и передавать строкам управляемые `open`/`onOpenChange`,
чтобы загрузка счетов нового месяца и временное размонтирование строк не сбрасывали раскрытие.

Повторять тип в строке не нужно: он уже обозначен секцией. На узком экране история использует
переносы/вертикальное расположение деталей без широкой табличной разметки. Не добавлять общий итог
по группе, поскольку в группе могут быть разные валюты.

Альтернатива — использовать `CardAmount` напрямую — не подходит из-за его поведения для пустых
items, отсутствия явного плюса и подписи итога. Изменять общий компонент ради этого виджета не нужно.

### 3. Краткий список последних 10 переводов каждого раскрытого счета

В строке вызвать `transfersQueryOptions.findAll` с `{ accountId, fromDate, toDate, page: 1,
limit: 10 }`, используя `enabled: open`. Размер страницы 10 обеспечивает краткую информацию
о последних переводах за выбранный месяц. Следующие страницы не запрашивать и не добавлять
элементы навигации. Не подключать общую первую страницу виджета Transfers: она может содержать
операции других счетов и давать ложную пустую историю конкретного счета.

Query key уже включает все параметры. Не использовать placeholder предыдущего месяца.
Внутри панели показывать skeleton при первой загрузке, QueryError с retry при отсутствии
пригодных данных и ошибке, пустое сообщение при успешном `items.length === 0`.
При фоновом обновлении за тот же период сохранять историю; при ошибке обновления показать
компактную ошибку рядом с кэшированными записями. Ошибка одной панели не блокирует остальные счета.

Существующая invalidation обновляет открытые истории после создания, редактирования и удаления
перевода. Для закрытого счета следующий запрос использует актуальность TanStack Query.
Новые entity-to-entity импорты не требуются: виджет импортирует публичные API entities.

### 4. Проекция эффекта перевода

Для текущего счета выбирать `source` со знаком минус или `destination` со знаком плюс. Показать
название второго счета без префиксов и сумму выбранной стороны в ее валюте в одной flex-строке,
а `transactionDate` отдельной строкой ниже. Длинное название сокращать с многоточием и сохранять
полное имя в title, чтобы строка оставалась компактной на узком экране.
Для форматирования использовать валютную точность существующих currency helpers с явным знаком.
Не восстанавливать эффекты через разницу snapshots и не рассчитывать конвертацию.

Полученную страницу сортировать по `transactionDate` от новых к старым, с id для одинаковой даты.
API списка не предоставляет параметра сортировки. До подключения проверить, что backend
возвращает последние переводы первыми до применения пагинации: сортировка произвольной
страницы на frontend не гарантирует выбор последних 10 записей. Если этот порядок не
подтвердится, зафиксировать несовместимость API с требованием и согласовать необходимое
изменение контракта; не подменять последние переводы произвольной первой страницей.

## Risks / Trade-offs

- [Более 10 переводов за месяц] → История намеренно ограничена 10 последними переводами согласно
  согласованному объему; не обозначать ее полной выпиской или объяснением всего баланса.
- [Много открытых счетов] → По одному запросу на раскрытый счет; закрытые строки не загружают
  историю заранее, query cache переиспользуется при повторном раскрытии.
- [Архивный второй счет] → Lookup использует полный ответ счетов; при отсутствии имени остается
  нейтральная подпись, сумма и дата доступны.
- [Расхождение со старым change] → Новая capability описывает именно dashboard widget; старые
  сценарии overview потребуют сверки при отдельной будущей синхронизации того change.
- [Ограниченная тестовая инфраструктура] → Не добавлять runner. Использовать существующий
  адресный `node:test` для `.mjs`, явно документировать команду для новых проверок и выполнить
  обязательные lint, architecture, build и ручную проверку UI.

## Migration Plan

Изменения только во frontend, миграция данных не требуется. Выпустить обычную сборку после
проверок. При откате вернуть реализацию виджета и его локализацию; API и данные не меняются.
