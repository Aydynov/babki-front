# Proposal

## Why

Виджет счетов смешивает расчетные, накопительные и архивные счета, не упорядочивает их по валюте и
не позволяет увидеть влияние переводов на отдельный счет. Нужен компактный обзор активных счетов
с понятными группами и раскрываемой историей переводов за выбранный месяц.

## What Changes

- Скрыть счета с непустым `archivedAt` только в виджете дашборда; сохранить их в управлении счетами.
- Разделить обзор на «Расчетные» и «Накопительные» в таком порядке.
- Внутри каждой группы сначала показывать счета в `defaultCurrency`, затем остальные по коду валюты;
  внутри валюты сортировать по имени.
- Добавить независимое раскрытие каждого счета с датой, названием второго счета и фактической
  суммой перевода со знаком минус для отправителя и плюс для получателя.
- В записи перевода показывать только название второго счета без «На счет» / «Со счета»;
  название и сумму располагать в одной строке, дату — ниже.
- Показывать краткий список из не более 10 последних переводов каждого раскрытого счета за
  выбранный месяц дашборда, одной страницей без пагинации и загрузки следующих страниц.
- Сохранить баланс на конец выбранного месяца и добавить локальные состояния загрузки, ошибки
  и отсутствия переводов, доступное раскрытие и адаптивное отображение.

## Capabilities

### New Capabilities

- `accounts-widget-presentation`: Отображение активных счетов по типам и валютам и раскрытие
  месячной истории влияния переводов на каждый счет.

### Modified Capabilities

Нет изменений основных спецификаций. Общие требования `widget-loading-states` сохраняются.

## Impact

- `src/widgets/accounts/`: группировка, сортировка, раскрываемые строки и история счетов.
- Публичные API `entities/accounts`, `entities/users`, `entities/transfers` и `select-period`;
  существующие `GET /accounts`, `GET /users/me` и `GET /transfers` без изменения DTO.
- Существующие Base UI Collapsible, общие UI-компоненты, форматирование валют и русская локализация;
  новых зависимостей и маршрутов не требуется.
- Предыдущий завершенный, но не архивированный change `adapt-frontend-to-multicurrency-api`
  содержит `personal-account-management`, которого пока нет в основных specs. Его сценарии
  допускают архивные счета в overview. Новая capability уточняет область: архивные доступны в
  управлении, но отсутствуют в виджете; старые артефакты не редактируются.
