# Design

## Context

Мотивация описана в `proposal.md`. Сейчас `Expenses` использует Accordion для вложенных позиций,
а `ExpenseActions` управляет отдельным `EditExpenseDialog`. Форма расхода сама рендерит Dialog.Content.
`DebtDetailsDialog` показывает подход с режимами view/edit и возвратом в просмотр после сохранения.
Изменение затрагивает виджет, feature и согласование кэша, поэтому требует общего дизайна.

## Goals / Non-Goals

**Goals:** единое окно просмотра/редактирования; повторное использование валидации и формы;
сохранение FSD, ограничений периода, прав и независимого меню удаления.

**Non-Goals:** новые API, изменение расчёта суммы, новые поля расхода, удаление из деталки,
переработка создания расхода или деталки долга.

## Decisions

### Единый владелец окна и режимов

Предлагаемая техническая реализация: `ExpenseDetailsDialog` в `features/manage-expense` управляет
выбранным расходом, режимом view/edit и update mutation. Виджет открывает view по строке,
меню запрашивает edit через callback. Feature экспортирует необходимые компоненты через index.ts.
Одна точка управления предотвращает одновременное открытие двух окон и дублирование состояния.

Альтернативы: отдельные окна просмотра и редактирования усложняют возврат и фокус;
readOnly-флаг у всей формы связывает просмотр с валидацией и загрузкой вариантов выбора.
Отдельный `ExpenseView` с текстовыми значениями соответствует выбранному пользователем виду деталки долга.

```text
row --> view --> edit --> save --> view(updated)
                 |
                 +--> cancel --> view(saved)
menu edit ------> edit
```

Кнопка отмены редактирования возвращает просмотр без подтверждения и сбрасывает черновик.
Escape в idle-edit возвращает просмотр; повторный Escape в просмотре закрывает окно.
Крестик и фон закрывают всё окно с отбрасыванием черновика. Отдельная «Отмена» рядом с сохранением возвращает просмотр. Пока идёт сохранение, закрытие и переходы блокируются. Ошибка оставляет форму.
После перехода в просмотр фокус остаётся в окне, после полного закрытия возвращается к строке
или кнопке меню, которая открыла окно.

### Переиспользование формы и актуальность данных

Сохранить `ExpenseForm` и существующие преобразования payload, ограничения валюты, счёта, даты,
участника и точности. Согласовать владение Dialog.Content без вложенных модальных контейнеров;
путь создания расхода должен сохранить текущее поведение.

Начальные данные уже присутствуют в строке: отдельный обязательный запрос деталей не нужен.
Подписи счёта и участников берутся из существующих scoped-кэшей; отсутствие справочников
не блокирует чтение самого расхода. Автор отображается через actorLabel, включая анонимизацию.
Позиции показываются полностью внутри прокручиваемого тела; итог берётся из сохранённого amount,
а не вычисляется по позициям заново.

После PATCH использовать возвращённый Expense немедленно для view и обновить соответствующие
scoped detail/list-кэши в query-модуле сущности. Сохранить существующую инвалидацию зависимых данных.
Ответы фонового чтения, начатого до сохранения, не должны заменять подтверждённый результат старой версией.
Сбой обновления зависимого виджета не превращает успешное сохранение в ошибку формы.

### Чтение доступно независимо от мутаций

Детали открываются для любого загруженного расхода. Edit доступен только в текущем периоде
при useCanManageRecord(createdBy, participantId) и подтверждённо неархивном счёте.
При неразрешённом состоянии счёта изменение недоступно до получения контекста; просмотр доступен.
Переназначение участника сохраняет отдельное существующее ограничение автора/manageTransactions.
Смена периода снимает ещё неотправленное редактирование и показывает saved view;
смена пользователя/пространства закрывает окно, исключая перенос данных между бюджетами.
Уже отправленное сохранение завершается в исходном scope.

### Строка без Accordion

Заменить Accordion обычным телом таблицы, удалить Trigger/Panel и вложенную таблицу.
Сохранить текущие мобильные карточки, фильтры, пагинацию, состояния загрузки и ошибки.
Открытие строки должно работать с клавиатуры и иметь понятное доступное имя без нарушения
семантики таблицы. Кнопки меню и повтора загрузки категории не активируют строку.
Пустое описание показывает «Нет описания» независимо от наличия позиций.

## Risks / Trade-offs

- Устаревший выбранный объект после сохранения → использовать результат мутации и синхронизировать scoped-кэши.
- Случайный переход по строке из меню → изолировать события интерактивных контролов.
- Потеря фокуса при замене формы → явное управление фокусом при смене режима и закрытии.
- Много позиций/длинные значения → прокрутка тела окна, перенос текста и проверка узкого экрана.
- Расхождение старой спецификации об архивном счёте с текущим UI → delta явно закрепляет просмотр без edit.

## Migration Plan

Серверная миграция не требуется. Заменить сценарий раскрытия и подключить единое окно вместе,
проверить сохранение существующих создания, редактирования и удаления. Откат — возврат frontend-изменения;
формат сохранённых расходов не меняется.
