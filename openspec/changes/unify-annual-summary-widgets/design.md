# Design

## Context

См. `proposal.md` для мотивации и `specs/annual-summary-presentation/spec.md` для поведения.
`YearSavings`, `YearIncomes` и `YearExpenses` используют общий `reportsQueryOptions.yearly()`,
данные пользователя и `getReportMetricSections`, но создают `CardAmount` для каждой валюты.
`LastYearRest` аналогично создает несколько `CardList`. Все четыре блока находятся в годовой колонке
`src/pages/main/ui/main-page.tsx`, ширина которой на desktop равна 18rem.

`getReportMetricSections` уже сохраняет нулевые валютные итоги выбранного года, сортирует валюты
и подставляет нулевую основную валюту при отсутствии валют отчета. Предыдущие значения сопоставляются
по коду валюты. Месячный `Incomes` демонстрирует подход с одним заголовком и валютными строками.

## Goals / Non-Goals

**Goals:**
- Изменить представление четырех блоков, сохранив существующий источник финансовых значений.
- Сделать формат строк трех показателей единообразным без импортов между widget-слайсами.
- Сохранить существующее поведение отсутствующих данных и скрытия бессодержательного сравнения.

**Non-Goals:**
- Новые API, пересчет накоплений, курсы валют или объединение денежных сумм.
- История операций, раскрытия, диалоги и создание операций из годовой сводки.
- Изменение месячных виджетов, графиков и глобальной логики цветов `CardAmount`.

## Decisions

### 1. Один общий презентационный компонент для трех показателей

Добавить небольшой компонент в `shared/ui` с публичным `index.ts`: одна оболочка, заголовок,
валютные строки и вариант окраски diff для расходов. Он получает готовые значения и состояние
содержимого, не импортирует entities, features или widgets и не выполняет запросы.
Три существующих виджета сохраняют владение запросами и выбором метрики.

Альтернативы: повторить одинаковую разметку в трех виджетах либо расширить `CardAmount`
до мультивалютного универсального контейнера. Первый вариант размножает оформление,
второй усложняет примитив с существующими месячными потребителями и раскрытиями.
Новый компонент ограничен годовой формой сводки, без системы настраиваемых колонок.

### 2. Компактные строки вместо вложенных карточек

Один заголовок сверху; затем код валюты, рядом diff, сумма справа.
Использовать существующие типографику, форматирование полного значения и токены цветов.
При нехватке места разрешить перенос внутри строки, сохраняя всю сумму.
Дополнительная подпись сравнения под валютными строками отсутствует.
На мобильном четыре карточки идут в одну колонку; desktop сохраняет годовую боковую колонку.

Не переносить действия месячных доходов: годовые показатели являются сводкой.
Переключатель валют отвергнут, поскольку скрывал бы независимые итоги и противоречил бы существующей спецификации.

### 3. Источник валют и сравнение остаются прежними

Использовать `getReportMetricSections` для выбранного и предыдущего года; не объединять валюты
разных лет и не добавлять отсутствующую основную валюту к непустому отчету.
Три карточки выбранного года имеют один состав валют, включая нулевые значения метрик.
«С прошлого года» использует собственный состав валют предыдущего года, который может отличаться.

Сохранить существующее правило `getPercent`: нулевое текущее значение, нулевая/отсутствующая база
или нулевой diff скрывают индикатор. Не менять общую функцию в рамках визуальной доработки.
Знак процента определяет стрелку; параметр окраски расходов инвертирует только цвет.
Для отрицательных значений сохранить существующую формулу, не вводить новую финансовую интерпретацию.

### 4. «С прошлого года» остается отдельной композицией

Одна `Card` с заголовком и валютными группами. В каждой группе код валюты над двумя строками:
«Остаток» и «Накопления», суммы справа в собственной валюте.
Использовать существующий `getReportCurrencySections` для предыдущего года.
Отсутствующий отчет показывает empty state; существующий отчет без валют сохраняет нулевую группу
основной валюты. Это сохраняет текущее различие без выдуманных данных.

Таблица с тремя колонками «валюта / остаток / накопления» отклонена: в колонке 18rem длинные суммы
будут конкурировать за место. Валютные группы лучше сохраняют подписи на мобильном экране.

### 5. Состояния принадлежат единой оболочке

Первичная загрузка отчетов или пользователя показывает skeleton строк внутри карточки с заголовком.
Ошибка без данных показывает один retry-блок внутри соответствующей карточки; пригодные кэшированные
данные сохраняются при фоновой ошибке с компактным сообщением. Использовать существующие query keys,
повтор обоих обязательных запросов и локализованные сообщения. Смена года выбирает значения из
общего годового ответа по новому году, без локального копирования прежних строк.

## Risks / Trade-offs

- Длинные полные суммы в узкой колонке → проверка нескольких валют и крупных сумм на desktop и 375px,
  перенос содержимого без обрезания и горизонтальной прокрутки страницы.
- Различный состав валют по годам → не выравнивать прошлогодний блок искусственно с текущим;
  каждый блок отображает валюты своего периода.
- Путаница между направлением и оценкой расходов → инвертировать только цвет, сохранить знак и стрелку.
- Зависимость от общей функции сравнения → сохранить текущие правила нулей; изменение формулы не входит в задачу.

## Migration Plan

Изменение только frontend, миграция данных и синхронное развертывание API не требуются.
Обновить три показателя, прошлогодний блок и при необходимости адаптивную сетку; выполнить проверки
из задач и сохранить screenshots. Откат — возврат UI-изменений без преобразования пользовательских данных.
